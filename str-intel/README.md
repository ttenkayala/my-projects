# STR Intel

A small STR investment analytics project that ingests Airbnb, Redfin-style, tourism-reference, and POI data, builds a DuckDB warehouse, and exposes a simple FastAPI + dashboard interface for LA and San Diego market screening.

## Project structure

- `run_pipeline.py` — builds schema, loads staging data, creates facts and marts
- `ingestion/` — source loaders
- `sql/` — schema and mart SQL
- `api/` — FastAPI service
- `dashboard/` — simple dashboard UI
- `data/raw/airbnb/` — Airbnb listing snapshots
- `data/raw/tourism_demand.csv` — neighborhood tourism and demographic reference data
- `data/poi/attractions.csv` — curated POI coordinates used for nearest-distance calculations
- `str_intel.db` — generated DuckDB database

## Setup

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Run pipeline

```bash
python run_pipeline.py
```

The pipeline loads Airbnb, Redfin-style, and tourism reference data, then rebuilds facts and marts. It currently loads 56,865 listing snapshots and 368 scored neighborhoods with the bundled data.

## Start API

```bash
python -m uvicorn api.main:app --host 127.0.0.1 --port 8000 --reload
```

Then open:

- http://localhost:8000/healthz
- http://localhost:8000/dashboard
- http://localhost:8000/markets?limit=10

Run the command from the project root. Starting uvicorn from the parent repository can cause `ModuleNotFoundError: No module named 'api'`.

## Notes

- The project includes a built-in sample Redfin fallback if the downloaded CA zip file is not present.
- Airbnb data should be placed in `data/raw/airbnb/` for the full dataset.
- The dashboard supports market/neighborhood listing drilldown, listing filters, sorting, and a selected-area context label.
- The current listing extracts do not include beds, baths, square footage, or structured amenities.
- Missing Airbnb prices may be generated by fallback logic; these values must be labeled before investment use.
- Tourism and demographic fields are bundled reference/proxy data, not yet documented authoritative figures.
- The POI file is curated and incomplete; nearest distances are useful for prototyping but require broader source coverage.
- Estimated occupancy is derived from availability rather than confirmed booking records.
